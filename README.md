## Что делает бот

1. Читает канал `@statamk10` с помощью Telethon (userbot). Обрабатывает
   и `NewMessage`, и `MessageEdited` — результаты раундов дописываются
   в исходное сообщение по мере игры, парсер корректно обновляет БД.
2. На каждом новом матче применяет многоуровневый анализ по
   Cybernagual (см. ниже).
3. Если все фильтры подтверждают вход — публикует сигнал в
   `SIGNAL_CHAT` через Bot API (python-telegram-bot) с указанием
   целевого диапазона раундов (1–3 или 4–6).
4. По завершении матча (`#TN`) закрывает сигнал: имитирует «Золотой
   догон» внутри целевого диапазона (три шага с увеличивающимися
   ставками), обновляет виртуальный банк и статистику.
5. Отвечает на команды `/start`, `/balance`, `/stats`
   (день / неделя / месяц).

## Как анализатор думает (источники указаны)

Последовательность шагов в `mkx_bot/analyzer.py` воспроизводит
алгоритм из урока **«Анализ коридоров времени и персонажей»**
(`docs/lessons/corridors.md`):

1. **Полнота данных.** Нужны имена обоих персонажей, коэффициенты на
   матч и на Fatality/Brutality. Без них вход не рассматривается.
2. **Персонажи-Палачи/Доноры** из ТЗ §2. П1 — Джейсон, Милина, Райдэн,
   Рептилия, Триборг. П2 — Соня Блейд, Джакс, Кэсси Кейдж, Ди'Вора
   (плюс английские варианты имен).
3. **Мёртвые минуты** (ТЗ §2): 03:00–04:30, 12:10, 12:40, 13:15,
   23:50–23:59 — блок.
4. **Волна Бритья** (ТЗ §2): если последние 3 *завершённых* матча в
   истории прошли без F и без B — вход заблокирован до первого
   Fatality.
5. **Коридоры времени** (`corridors.md`, `Fatality.md`). Сутки
   разделены на 288 пятиминутных коридоров. Для каждого считается
   P(F) отдельно для диапазонов **1–3** и **4–6** раундов. Коридор
   «голосует» за диапазон, если:
   - в нём P(F) ≥ `corridor_prob_min` (по умолчанию **0.65** — минимум
     из урока, рекомендация — ≥ **0.88**), и
   - P(F) по этому диапазону **заметно выше** (margin **+0.10**) чем
     по другому диапазону — это как раз та рекомендация «предпочтительно,
     чтобы вероятности разных диапазонов существенно отличались».
6. **Фатовость персонажей** (`Fatality.md` §Таблицы Fatality). Для
   каждой стороны отдельно смотрим P(F) по 4 окнам: последние 50, 30,
   10, 5 матчей; главная выборка — 50. Пороги из урока зависят от
   бакета коэффициента на Fatality:
   - кф 2.00–2.99 → порог **80%**
   - кф 3.00–3.99 → порог **70%**
   - кф 4.00–4.99 → порог **60%**
   - Разброс выборок (волатильность) относительно основной — не более
     **0.30**.
7. **«Базовая закономерность» коэффициента** (`Fatality.md`
   §Коэффициентный анализ). Конец целого диапазона (напр. 2.94) имеет
   ниже реальной проходимости, чем начало следующего (3.05). Если кф
   на Fatality попадает в последние 15% диапазона — ставим блок
   (`tail_of_range_threshold`).
8. **Кросс-фильтрация FatBrut** (`FatBrut.md` §Объяснение противоречия).
   Для ставки на Fatality правильный срез строится по коэффициенту
   на *Brutality* (а не на Fatality). Проверяем, что в истории есть
   матчи с близким кф на Brutality (± 0.10) — это оценка того, что
   наш матч «имеет алгоритм для анализа». Если срез абсолютно пуст —
   блок (нельзя ставить «вслепую»).
9. **Итог.** Сигнал идёт, только если *нет* блокеров и выбран
   целевой диапазон.

## Ставки — «Золотой догон» (ТЗ §4)

- Стартовый банк **1000**.
- Базовые ставки: Р1 = **100**, Р2 = **220**, Р3 = **480**.
- Масштабирование: каждая ставка умножается на `current_balance / start_balance`.
- Внутри целевого диапазона (напр. раунды 1–3) бот делает три
  виртуальных шага. Если в раунде k появляется `F` — шаг выигран по
  кф из поля `FBR` сообщения, остальные шаги отменяются. Если
  диапазон закрыт без `F` — все три шага проиграны.

## Парсинг сообщений (ТЗ §3)

Парсер `mkx_bot/parser.py` извлекает:

- заголовок `22:05 12-05-2026 #N230 #L2` → время/дата/номер/линия,
- русские имена `#Хищник #Горо` и английские `Predator - Goro`,
- коэффициенты `P1m|P2m - 1.504|2.65`, `P1/P2 - 1.74/2.19`,
- `FBR - 3.6 | 3.45 | 1.955` → Fatality / Brutality / БД,
- раунды `1. P1--B--22 TMM` — победитель, тип финишера (F/B/R),
  длительность в секундах, метка времени (TM/TMM/TB),
- завершение матча по тегу `#T<N>`.

`MessageEdited` поддержан штатно: `UPSERT` не стирает ранее
заполненные поля, только добавляет новые.

## Первый запуск и авторизация

Бот использует **Telethon-userbot** для чтения канала (это ваш
аккаунт, а не бот) и **python-telegram-bot** для публикации сигналов
(это бот от `@BotFather`).

**Шаг 1. Получаем ключи:**

- `TELETHON_API_ID` / `TELETHON_API_HASH` — на `https://my.telegram.org`
  (раздел *API development tools*).
- `TELEGRAM_BOT_TOKEN` — у `@BotFather` командой `/newbot`.

**Шаг 2. Заполняем `.env` (кроме `SIGNAL_CHAT`, если это приватная группа):**

```bash
cp .env.example .env
# отредактируйте .env: TELETHON_API_ID/HASH, TELEGRAM_BOT_TOKEN,
# SOURCE_CHANNEL (@statamk10 по-умолчанию)
```

**Шаг 3. Узнаём id группы, куда бот должен писать:**

- Создайте/откройте группу.
- Добавьте туда вашего бота (из `@BotFather`) как **администратора** с
  правом отправки сообщений.
- Напишите в группе команду `/start`. Бот ответит сообщением с
  `chat_id этой группы: -100...`. Скопируйте это число в `.env`:

  ```env
  SIGNAL_CHAT=-1001234567890
  ```

  (Для публичных групп/каналов можно просто `SIGNAL_CHAT=@my_group`.)

**Шаг 4. Запускаем:**

```bash
pip install -r requirements.txt
python main.py
```

При **первом** запуске Telethon попросит (в том же терминале):

```
============================================================
  ВХОД В АККАУНТ TELEGRAM (Telethon / userbot)
============================================================
Введите номер телефона (например, +79001234567):
Phone: +79001234567
Введите код из SMS / Telegram: 12345
```

Если на аккаунте включена двухфакторная защита — дополнительно
попросит пароль 2FA. После успешного входа создаётся файл
`mkx_session.session` — в нём хранится авторизация, при следующих
запусках ничего вводить не нужно.

> **Важно:** никому не передавайте файл `.session` и `.env` —
> они уже в `.gitignore`. С ними чужой человек получает полный
> доступ к вашему аккаунту Telegram.

**Шаг 5. Проверка:** в логах должно появиться
`MKX bot started. Listening @statamk10 → publishing to -100...`.
С этого момента при подходящих матчах сигналы будут приходить
в указанную группу (а не вам в личку).

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Приветствие |
| `/balance` | Текущий банк и размер шагов догона с учётом масштабирования |
| `/stats` | Итоги сигналов за день/неделю/месяц: количество, W/L, WR, суммарный профит |

## Почему именно такие числа

Все пороги вынесены в `mkx_bot/config.py` и подкреплены ссылками на
конкретный раздел урока. Если завтра Cybernagual обновит
рекомендации (порог 65 → 70, бакет 2.5–2.99 → 2.2–2.99 и т.п.), это
одна правка одного места. Логика модулей остаётся прежней.
