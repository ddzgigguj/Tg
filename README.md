# MKX Telegram Bot (Cybernagual «Золотой догон» v3.0)

Telegram-бот, построенный по ТЗ из файла
`Промт_для_создания_Telegram-бота_MKX_на_основе_стр.pdf`.
Бот мониторит канал со статистикой Mortal Kombat X, анализирует матчи
по многоуровневой стратегии Cybernagual и публикует сигналы в
указанную группу только при пересечении нескольких фильтров.

## Что реализовано

| Модуль                  | Назначение                                                      |
|-------------------------|-----------------------------------------------------------------|
| `mkx_bot/config.py`     | Загрузка `.env`, константы стратегии (Палачи, Доноры, фильтры). |
| `mkx_bot/models.py`     | Dataclass-модели `Match`, `Round`, `ParsedMessage`.             |
| `mkx_bot/parser.py`     | Все регулярки для формата @statamk10 (заголовок, имена, коэффициенты, раунды, #T*). |
| `mkx_bot/db_manager.py` | SQLite: матчи, раунды, сигналы, история баланса, `/stats`.      |
| `mkx_bot/balance.py`    | Стартовый баланс 1000; ставки Р1=100, Р2=220, Р3=480; масштабирование пропорционально балансу. |
| `mkx_bot/analyzer.py`   | Фильтры: персонажи, мертвые минуты, коридоры времени (288 × 5 мин), Волна Бритья, пересечение срезов. |
| `mkx_bot/bot.py`        | Telethon (чтение канала, `NewMessage` + `MessageEdited`) + python-telegram-bot (отправка сигналов, `/stats`, `/balance`). |

## Фильтры стратегии

- **Персонажи-Палачи (П1):** Джейсон, Милина, Райдэн, Рептилия, Триборг.
- **Персонажи-Доноры (П2):** Соня Блейд, Джакс, Кэсси Кейдж, Ди'Вора.
- **Волна Бритья:** если последние 3 матча без добиваний — вход
  блокируется до первого Fatality.
- **Мертвые минуты:** 03:00–04:30, 12:10, 12:40, 13:15, 23:50–23:59.
- **Коридоры времени:** 288 пятиминутных окон в сутки, эмпирическая
  вероятность Fatality строится по накопленной истории в SQLite.
- **Пересечение срезов:** сигнал идет только если одновременно
  подтверждаются ≥3 независимых фильтра и ни один не блокирует вход.

## Парсинг сообщения (формат из ТЗ)

```
22:05 12-05-2026 #N230 #L2
#ХищникГоро
#Хищник #Горо
Predator - Goro
   P1m|P2m - 1.504|2.65
P1/P2 - 1.74/2.19
FBR - 3.6 | 3.45 | 1.955
#t8v7     atv : 33.17
...
1. P1--B--22  TMM
2. P2--R--26  TM
...
   #T8
```

Парсер вытаскивает:

- Время (`22:05`), дату (`12-05-2026`), номер матча (`#N230`), линию (`#L2`).
- Русские имена (`#Хищник #Горо`) и английские (`Predator - Goro`).
- Коэффициенты: `P1m|P2m`, `P1/P2`, `FBR`.
- Раунды вида `N. P1--B--22  TMM` (победитель, финишер F/B/R, секунды).
- Признак завершения матча по тегу `#TN`.

Повторные сообщения (`MessageEdited`) обрабатываются штатно: в БД
уже известные поля не затираются, новые — дописываются.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env       # заполнить реальными значениями
python main.py
```

Необходимо задать:

- `TELETHON_API_ID`, `TELETHON_API_HASH` — [my.telegram.org](https://my.telegram.org).
- `TELEGRAM_BOT_TOKEN` — из [@BotFather](https://t.me/BotFather).
- `SIGNAL_CHAT` — чат/канал для публикации сигналов (@username или id).
- `SOURCE_CHANNEL` — по умолчанию `@statamk10`.

## Команды

- `/start` — приветствие.
- `/balance` — текущий баланс и размер ставок.
- `/stats` — статистика сигналов за день/неделю/месяц (всего, W/L, WR, профит).

## Структура кода (из ТЗ §6)

1. `analyzer.py` — фильтры, коридоры, персонажи, Волна Бритья.
2. `db_manager.py` — SQLite, история, серии БД.
3. `balance.py` — виртуальные ставки и профит.
4. `bot.py` — основной цикл Telethon + Bot API.

## Замечание про материалы Cybernagual

В ТЗ приведены ссылки на уроки и статьи на `teletype.in/@cybernagual`
(Урок 1, Урок 2, Fatality & Brutality, Интуиция vs Статистика,
Коридоры, Фичи, FAQ и др.). Среда выполнения этого репозитория
находится в ограниченной сети (HTTP 403 на `teletype.in` через
корпоративный прокси), поэтому тексты уроков не удалось автоматически
скачать. Логика бота реализована строго по описанию из самого PDF;
константы (список Палачей/Доноров, «мертвые минуты», параметры
«Волны Бритья», 288 коридоров × 5 мин, начальный баланс и ставки
100/220/480) заданы в `config.py` и при необходимости правятся в
одном месте без изменения кода.
